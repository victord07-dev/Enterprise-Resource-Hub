──────────────────────────────────────────────────────────────
REPORT 1 — Customer Aging (implements T9 getCustomerAging stub)
──────────────────────────────────────────────────────────────

Aggregator (financial-aggregations.ts):
getCustomerAging(asOf?: string, customerId?: string)

Logic:
- For each customer (or single customer if customerId passed):
  fetch all sales_invoices that have outstanding > 0
- Outstanding per invoice = computeCustomerInvoiceOutstanding()
  — canonical helper, no inline math
- Age each invoice: days from invoice dueDate to asOf 
  (default today)
- Bucket per customer into: Current (not yet due), 
  1-30 days, 31-60 days, 61-90 days, 90+ days
- Output per customer row: name, total outstanding, bucket 
  amounts, oldest invoice date

Route: GET /api/reports/customer-aging?asOf=&customerId=

UI (new tab or page, operator decides placement — surface 
options before building):
- As-of date picker (single date, default today)
- Optional customer filter dropdown
- Table: Customer | Total Outstanding | Current | 1-30 | 
  31-60 | 61-90 | 90+ | Oldest Invoice
- Status color coding: current = green, 1-30 = amber, 
  31-60 = orange, 61-90 = red, 90+ = dark red
- Summary bar chart (Recharts): stacked bar per bucket 
  across all customers
- 3 download buttons: CSV, Excel (ExcelJS), PDF (jsPDF + 
  drawLetterhead + Noto Sans)
- Indian number formatting throughout

REPORT 3 — Cash Position (implements T14 getCashPositionReport)
──────────────────────────────────────────────────────────────

Note: getCashPositionPerAccount() is already implemented 
(returns current balance per account). T14 getCashPositionReport 
extends this with as-of-date support and period inflow/outflow 
breakdown.

Aggregator:
getCashPositionReport(asOf?: string)

Logic per account:
- Opening balance = computeAccountBalance(accountId, 
  day before asOf start of FY or period start)
- Inflows in period = SUM(customer_payments) + 
  SUM(positive balance_adjustments) + SUM(incoming 
  account_transfers)
- Outflows in period = SUM(supplier_payments) + 
  SUM(expenses) + SUM(negative balance_adjustments) + 
  SUM(outgoing account_transfers)
- Closing balance = computeAccountBalance(accountId, asOf)

Route: GET /api/reports/cash-position?asOf=

UI: Table per account + consolidated total row. Bar chart 
(Recharts) showing opening vs closing per account. 
3 download buttons.

──────────────────────────────────────────────────────────────
REPORT 4 — Account Statement (implements T15 getAccountStatement)
──────────────────────────────────────────────────────────────

Aggregator:
getAccountStatement(accountId: string, p: PeriodFilter)

Logic:
- Opening balance = computeAccountBalance(accountId, 
  day before p.from)
- UNION all transactions for accountId in period from 5 
  source tables:
  customer_payments WHERE cashAccountId = accountId → 
    type='Receipt', amount positive
  supplier_payments WHERE cashAccountId = accountId → 
    type='Payment', amount negative
  expenses WHERE cashAccountId = accountId → 
    type='Expense', amount negative
  account_transfers WHERE fromAccountId = accountId → 
    type='Transfer Out', amount negative
  account_transfers WHERE toAccountId = accountId → 
    type='Transfer In', amount positive
  balance_adjustments WHERE cashAccountId = accountId → 
    type='Adjustment', amount = adjustmentAmount (signed)
- Sort all rows by date ASC, then compute running balance 
  after each row (opening + cumulative)
- Output: date, type, description/reference, debit, credit, 
  running balance

Route: GET /api/reports/account-statement?accountId=&from=&to=

UI: Account selector dropdown (cash_accounts list), 
DateRangeFilter, table with running balance column, opening 
and closing balance rows pinned. 3 download buttons.

REPORT 5 — Consolidated Cash Statement 
(implements T16 getConsolidatedCashStatement)
──────────────────────────────────────────────────────────────

Aggregator:
getConsolidatedCashStatement(p: PeriodFilter)

Logic: Same UNION as Account Statement but across ALL accounts. 
Group rows by account with subtotals. account_transfers between 
internal accounts net ₹0 consolidated (show both legs but label 
as internal). Consolidated opening + closing = SUM across all 
accounts.

Route: GET /api/reports/consolidated-cash?from=&to=

UI: Grouped table (per-account section + consolidated footer). 
Stacked bar chart (Recharts) per account over period. 
3 download buttons.

──────────────────────────────────────────────────────────────
REPORT 6 — Cash-basis Ledger (Report 10C, new — not stubbed)
──────────────────────────────────────────────────────────────

New aggregator (financial-aggregations.ts):
getCashLedger(from: string, to: string, accountId?: string)

Logic: Same UNION as Account Statement. If accountId passed, 
filter to that account. If not, show all accounts 
chronologically in one unified ledger. Running balance tracks 
the consolidated cash position across all accounts (or single 
account if filtered). Sort strictly by date ASC, then 
createdAt for same-day tie-breaking.

Output per row: date, account name, transaction type, 
party name (customer/supplier/vendor), reference number, 
debit, credit, running balance.

Route: GET /api/reports/cash-ledger?from=&to=&accountId=

UI: DateRangeFilter + optional account filter. Full-width 
table. Running balance column. Opening and closing balance 
header/footer rows. 3 download buttons (CSV formatted for 
Tally import).
