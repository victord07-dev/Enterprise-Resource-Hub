2. Critical New Complexity Introduced by Luminous
A. Dealer vs Distributor Pricing (Two-Tier)
Luminous has separate price lists for distributors and dealers. The same product has two different base prices:
ModelDistributor PriceDealer PriceDifferenceOPTIMUS 2300+ (2KVA/24V)₹9,632₹10,210~6% markupECO VOLT NEO 1050₹4,434₹4,700~6% markupNXG 850e₹4,080₹4,325~6% markup
Your company (ITFI Group) buys at distributor price from Luminous. When you sell to your customers, you need to know if they're dealers (get dealer price as reference for your margin) or end users.
B. MRP Now Present
All Luminous products have an MRP. Eastman doesn't publish MRP. This affects how your salespeople quote — they reference MRP as the ceiling.
C. GST Rate Discrepancy — IMPORTANT
Luminous charges 18% GST on solar PCUs/inverters, while Eastman charges 12%. This is not an error in the data:

Eastman claims 12% concessional rate under solar energy device notifications
Luminous may classify the same products under a different HSN code attracting 18%
Check with your CA before setting GST rates — this affects every invoice you raise and every return you file
In the system, store the GST rate as-is per product (Eastman products at 12%, Luminous solar PCUs at 18%)

D. Region Exclusions on Price Lists
Luminous HKVA and Inverter/Battery lists are "PAN India excluding West region and South region." Different prices apply to different zones — same complexity as Eastman panel pallets but for more products.
E. SPGS Combos are Enormous
Luminous SPGS (Solar Panel Generation Systems) has 500+ combination SKUs across pages 2-9 of the distributor list. Each combines a specific inverter model + specific battery model (with qty) + specific panel model (with qty). This dwarfs even the Eastman Lith Combo problem.

3. What's The Same Across Both Brands

Distributor Basic Price / Net Effective Price = your buying cost (enters as GRN buyingPrice)
GST on solar panels = 5%
GST on solar charge controllers = 5%
GST on large hybrid/GTI inverters = 5%
Products need: name, SKU, brand, category, HSN, unit, warranty, specs

Part 2: The "Employee Can Add Custom Fields" Requirement
The requirement is that employees can add custom spec data from inside the product form itself without waiting for a developer.
Solution: Dynamic Specs with Custom Fields
Use the specs JSONB column as a flexible bag of key-value pairs. The product form shows:

Pre-defined spec fields shown automatically when category is selected (VA rating, voltage, etc.)
"+ Add Custom Field" button at the bottom of the specs section that lets any employee add a new key-value pair (text/number/dropdown)
Spec suggestions — if 3+ products already have the same custom key, it graduates to a "suggested" spec for that category (shown in the pre-defined section next time)

This way specs are extensible by the team without code changes.

Phase 7 — Bulk Import Endpoint (Priority before entering 300+ products manually)
Effort: ~1 day | Risk: Low
Goal: Allow importing products from a CSV/Excel file so the team doesn't enter 300+ products one by one.
Task 7.1 — Create POST /api/products/import endpoint in server/routes.ts
Accepts: multipart/form-data with a CSV file
CSV columns (all optional except name and category):
  name, sku, brand, category, description, unitPrice, gstRate, hsnCode,
  unit, minStockLevel, minMarginPct, warrantyPeriod, mrp, type

Processing:
  - Parse CSV row by row
  - For each row: validate required fields, check for duplicate SKU
  - If SKU already exists: skip (do not overwrite) and log to skipped list
  - If SKU is blank: auto-generate from name + timestamp
  - Insert valid rows in a transaction
  - Return: { imported: N, skipped: M, errors: [...] }
