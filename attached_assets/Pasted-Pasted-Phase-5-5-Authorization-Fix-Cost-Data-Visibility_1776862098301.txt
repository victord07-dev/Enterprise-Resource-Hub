Phase 5.5 Authorization Fix — Cost Data Visibility Boundary
Standing rule: before declaring complete, log in as a sales-role user and walk every affected path in the UI. Show screenshots of (a) quotation line with FloorPriceRefPanel visible (b) Network tab payload for effective-prices-today request with cost fields stripped (c) absent "Check Margin" button. Operator declares closure.
Problem statement:
Phase 5.5 Section A2 required sales-role users to see effectivePrice + floor prices, but NOT supplierPrice, distributorPrice, blendedCost, costPrice, or any landed-cost/margin data. Current implementation leaks blendedCost via effective-prices-today to all authenticated users. MarginSimPanel + "Check Margin" button are visible to sales roles. CEO-stated authorization boundary is violated.
Role definitions (existing, per Pricing.tsx line 46):

canManagePricing = admin / sales_manager / accountant
Non-privileged = sales, kiosk, field_staff, (any other role)

Fix scope:
1. Server-side field stripping on every endpoint that returns cost data to the client.
Audit the following endpoints and strip these fields from responses when req.user.role NOT IN (admin, sales_manager, accountant):
Fields to STRIP for non-privileged users: blendedCost, supplierPrice, distributorPrice, costPrice, logisticsCost, landedCost, avgLandedCost, marginPct, pressureRatio, supplierPriceFromPrimary, avgCostPerLot, any field in a lot breakdown (lots[]), any grn_* cost fields, any WAC/weighted-average-cost fields.
Fields to KEEP for all authenticated users: effectivePrice, strictFloorPrice, globalFloorPrice, unitPriceFallback, hasConfirmedPricingToday, source, sheetDate, productId, proposedPrice (if status=confirmed only), mrp, warrantyPeriod.
Endpoints to audit explicitly (minimum):

/api/daily-price-sheets/effective-prices-today
/api/daily-price-sheets/:id (GET) — used by the Pricing dialog; this should be fully role-gated (deny for non-privileged, not just strip)
/api/daily-price-sheets?sheetDate=... (listing) — strip for non-privileged
/api/primary-supplier-prices or whatever Phase 6.6 C6 added for the Pricing page — fully role-gated (deny for non-privileged)
/api/products and /api/products/:id — check if these return costPrice, distributorPrice, logisticsCost to the client. If yes, strip for non-privileged. unitPrice, mrp, gstRate, hsnCode stay visible to all.
/api/inventory-stock — should be fine (quantity only), but verify no cost fields leak
Any /api/reports/* endpoints that might return cost analytics

For each endpoint: either strip fields from the response payload OR return 403 for non-privileged users, whichever fits that endpoint's purpose better. Stripping is correct when the endpoint is legitimately needed by sales (e.g., effective-prices-today). Denying is correct when the endpoint's entire purpose is cost analytics (e.g., the Pricing detail endpoint).
2. Client-side: hide UI surfaces that expose cost data to non-privileged users.

"Check Margin" button on quotation/sales-order line editor: hide entirely for non-canManagePricing roles
MarginSimPanel component: unmount entirely for non-canManagePricing roles (don't render + hide — unmount, so it can't be toggled via devtools)
FloorPriceRefPanel: continues to render for all — it only uses effective + floor + max discount, all of which sales can see
Any cost columns in reports or tables visible to sales: hide
Pricing page itself (/pricing route): already route-gated behind canManagePricing in App.tsx — verify nothing regressed, but don't change

3. Defense in depth: test direct-API access as well as UI.
A sales user with devtools or curl could hit restricted endpoints directly. Server-side guards must enforce — don't rely on client hiding alone. This is why fix #1 matters more than fix #2.
4. Non-regression for privileged users.
Admin / sales_manager / accountant users must continue to see every cost field, the Check Margin button, the MarginSimPanel, the full Pricing dialog, and the Pricing page. No degradation for them.
