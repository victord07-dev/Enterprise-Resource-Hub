Phase 3: Operational Refinements

CONTEXT

ITFI's operational workflow has surfaced specific gaps that need
addressing. CEO has reviewed the current system and wants:

1. Manual stock adjustment to be removed from UI access (kept in code
   for future re-enablement).
2. Delivery challan workflow tightened: mandatory vehicle/driver
   fields + CEO-issued Delivery Order before dispatch can occur.

   entry (supplier challan number text field). Generic file upload

   only. Add GRN PDF download.

5. Sales Invoices page redesigned for clarity and responsiveness.

This phase is operational polish, not new functional capability. No
schema migrations expected to be heavy; mostly additive fields.

SECTION B — DELIVERY CHALLAN WORKFLOW EXTENSION

B1. Schema additions to delivery_challans table:
    physical_challan_number (text, NOT NULL after migration —
                             required field at "Mark Ready" time)
    vehicle_number (text, NOT NULL)
    vehicle_owner_name (text, NOT NULL)
    driver_name (text, NOT NULL)
    driver_phone (text, NOT NULL — Indian 10-digit mobile)
    do_issued_at (timestamp, nullable)
    do_issued_by (uuid FK → users, nullable)

B2. Status enum update:
    Existing: 'draft' | 'awaiting_signature' | 'dispatched' | 'cancelled'
    New: 'draft' | 'ready' | 'do_issued' | 'dispatched' | 'cancelled'

    Migration:
    - Existing rows with status='awaiting_signature' → migrate to 'ready'
    - Existing rows with status='dispatched' → stay as 'dispatched'
    - Other statuses unchanged

    Note: 'awaiting_signature' name is replaced by 'ready' — clearer
    operational meaning. The signed-copy-upload step from Phase 1 is
    being replaced by the new field-entry + DO-issuance workflow.

B3. Run db:push. Migration must preserve existing dispatched challans.

B4. Form fields at "Create Dispatch Challan" dialog:
    Current fields (keep): items list, source warehouse, notes
    Now ALL required (asterisk, no "(optional)" label):
    - Real Challan No. — text (the printed paper challan reference)
    - Vehicle No. — text
    - Vehicle Owner Name — text
    - Driver Name — text
    - Driver Phone — text, with Indian mobile validation:
      regex /^(\+91)?[6-9]\d{9}$/ — accept "9876543210" or "+919876543210"
      Reject if not valid

    Submit button on form is disabled until all 5 new fields filled
    AND validation passes.

B5. Mark Ready transition (draft → ready):
    - Available to: warehouse_manager, sales_manager, admin
    - Hard-blocked unless ALL THREE:
      a. Stock is sufficient for ALL line items (existing Phase 1 check)
      b. Linked Sales Order is fully paid (existing Phase 1 check)
      c. All 5 mandatory fields filled with valid values
    - On success:
      * Status → 'ready'
      * Existing ready_for_signature_at, ready_for_signature_by recorded
        (rename if needed; or keep field names, mappings same)
      * Notification fires to admin (CEO) ONLY:
        "Challan #[NUMBER] ready for delivery order. Vehicle: [vehicle_no],
         Driver: [driver_name]"
        Notification deep-links to /inventory route with challan tab
        + auto-opened challan detail (URL parameter or similar pattern)
      * Audit log: action='challan_ready'

    REMOVE from Phase 1: signed_copy_url upload requirement at this
    transition. Operator no longer uploads anything at this step.

B6. Issue Delivery Order transition (ready → do_issued):
    - Available to: admin ONLY (CEO)
    - Visible button on challan detail in Inventory > Challan tab:
      "Issue Delivery Order" (or "Approve Dispatch" — pick one term,
      use consistently)
    - Click button → confirmation modal: "Issue Delivery Order for
      Challan #[NUMBER]? Vehicle: [vehicle_no], Driver: [driver_name]
      ([driver_phone])"
    - On confirm:
      * Status → 'do_issued'
      * do_issued_at, do_issued_by recorded
      * Notification fires to warehouse_manager + sales_manager:
        "Delivery Order issued for Challan #[NUMBER]. Proceed with
         dispatch."
        Deep-links to /inventory > Challan tab > this challan
      * Audit log: action='delivery_order_issued'

B7. Dispatch transition (do_issued → dispatched):
    - Available to: warehouse_manager, sales_manager, admin
    - Hard-blocked if status != 'do_issued'
    - REMOVE Phase 1 signed_copy_url requirement at dispatch
    - On dispatch:
      * Status → 'dispatched'
      * dispatched_at, dispatched_by recorded
      * Stock movement created (existing logic — preserve)
      * Inventory deducted (existing logic — preserve)
      * AUTO-CREATE sales_invoice row (existing Phase 1 logic — preserve)
      * Notification to accountant + admin: "Challan #[NUMBER] dispatched"
      * Audit log: action='challan_dispatched' + 'sales_invoice_auto_created'

B8. Cancel Challan:
    - Available on draft, ready, do_issued (NOT after dispatch)
    - Required: cancellation_reason
    - Available to: sales_manager, admin
    - Audit log: action='challan_cancelled'

B9. Document Status Panel (Sales Order detail page → Documents section):
    For each linked challan, display NEW info:
    - Status badge (Draft / Ready / DO Issued / Dispatched / Cancelled)
    - Real Challan No. (if filled)
    - Vehicle No., Driver name + phone (compact display)
    - "View" / "Issue DO" / "Cancel" buttons per status + role

B10. Notification deep-linking:
    When CEO clicks notification in bell, URL navigates to:
    /inventory?tab=challans&challanId=[ID]
    Inventory page reads URL params on mount, switches to challans tab,
    auto-opens that challan's detail panel.

    Same pattern for warehouse notification: deep-links to challan tab
    with that specific challan focused.

SECTION C — GRN SIMPLIFICATION + PDF DOWNLOAD

C1. Schema changes to goods_receipt_notes:
    Add: supplier_challan_number (text, NOT NULL — the supplier's
                                  paper challan reference number)

    Keep but make NULLABLE (no longer required):
    - supplier_challan_url (was NOT NULL after upload in Phase 1)
    - signed_copy_url (was required at confirmation in Phase 1)
    - supplier_invoice_url (was already optional)

    The url fields stay in schema for any existing data + future use,
    just not enforced at workflow gates.

C2. Run db:push. Migration must preserve existing GRNs.

C3. GRN creation flow:
    - Replace Phase 1's "Upload Supplier Challan first → Create GRN"
      flow
    - New flow: User on PO detail clicks "Receive Goods" / "Create GRN"
      directly. Form opens with:
      * Supplier Challan No. — required text input (the paper reference)
      * Per-line item received quantities
      * Optional notes
    - On submit: GRN row created with status='draft',
      supplier_challan_number stored, supplier_challan_url left NULL
    - Audit log: action='grn_drafted'

    Supplier payment full-payment gate from Phase 1: PRESERVE this
    check. GRN cannot be created if PO not fully paid to supplier.

C4. GRN confirm flow (draft → confirmed):
    - REMOVE signed_copy_url upload requirement
    - REMOVE supplier_challan_url presence requirement
    - Available to: warehouse_manager, accountant, admin
    - Required: line items received quantities filled (existing logic)
    - On confirm:
      * Status → 'confirmed'
      * confirmed_at, confirmed_by recorded
      * Stock added to inventory (existing logic — preserve)
      * GRN lots created for FIFO costing (existing logic — preserve)
      * Notification to admin + accountant: "GRN #[NUMBER] confirmed.
        Stock updated."
    - Audit log: action='grn_confirmed'

C5. GRN expanded view — generic file upload section:
    - Move existing generic file upload from front column to expanded
      view (it's currently in the front column per operator)
    - Strip dropdown options from {challan, invoice, others} to ONLY
      "Others" (or rename label to "Additional Documents")
    - Existing supplier challan + signed GRN buttons (Phase 1) remain
      visible in expanded view as separate explicit upload controls,
      but their requirement gates are now removed (per C3, C4)
    - Functionally: uploads still work and store in attachments table,
      but no workflow gate depends on them

C6. Add GRN PDF download (was spec'd in Phase 1 but apparently not
    shipped):
    - Server-side endpoint: GET /api/grns/:id/pdf
    - Returns PDF document with:
      - ITFI letterhead (same as PO PDF — reuse company const)
      - Title: "GOODS RECEIPT NOTE"
      - GRN number, date, status
      - Supplier info: name, address, GSTIN
      - PO reference: PO number, PO date
      - Supplier Challan No. (the new field)
      - Line items table: item description, HSN, ordered qty,
        received qty, discrepancy (if any)
      - Signature line at bottom: "Authorized Signatory: ___________"
      - DRAFT watermark when status='draft'
      - CANCELLED watermark when status='cancelled' (if you have
        cancelled status — confirm; if not skip)
    - Available to: warehouse_manager, accountant, admin
    - "Download PDF" button on GRN detail/expanded view
    - Audit log: action='grn_pdf_downloaded'
