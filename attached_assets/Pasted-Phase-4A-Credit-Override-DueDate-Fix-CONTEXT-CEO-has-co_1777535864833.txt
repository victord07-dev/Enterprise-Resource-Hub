SECTION C — SALES-SIDE CREDIT OVERRIDE
==========================================================

C1. Modify POST /api/delivery-challans/:id/ready-for-signature:
    Accept new optional body fields:
    - creditOverride: boolean (default false)
    - creditReason: string (required if creditOverride = true)

    Logic:
    - Existing checks (stock, 5 mandatory fields) preserved
    - If SO.paidAmount >= SO.totalAmount: proceed normally (no
      override needed)
    - If SO.paidAmount < SO.totalAmount AND creditOverride = false:
      return 400 "Customer payment incomplete" as today
    - If SO.paidAmount < SO.totalAmount AND creditOverride = true:
      * Require req.user.role === 'admin' (otherwise 403 "Only admin
        can authorize credit dispatch")
      * Require creditReason is non-empty string (otherwise 400)
      * Compute creditAmount = SO.totalAmount - SO.paidAmount
      * Update challan: status='ready', is_credit_override=true,
        credit_amount=creditAmount, credit_approved_by=req.user.id,
        credit_approved_at=now(), credit_reason=creditReason
      * Audit log: action='challan_credit_override', module='sales',
        details=`Challan ${challan.number} ready-for-signature with
        credit override of ₹${creditAmount}. Reason: ${creditReason}`
      * Notification: notifyRoles(['accountant'], type='credit_override',
        title=`Credit dispatch approved: Challan ${challan.number}`,
        message=`Admin approved ₹${creditAmount} credit on
        Challan ${challan.number}. Reason: ${creditReason}`,
        relatedId=challan.id)

C2. UI — Mark Ready button on Inventory > Challans tab:

    When SO.paidAmount >= SO.totalAmount:
    - Existing "Ready" button (no change)

    When SO.paidAmount < SO.totalAmount AND user role !== 'admin':
    - Button label: "Ready" (greyed out)
    - Disabled
    - Tooltip: "Customer payment incomplete: Outstanding ₹X. Only
      admin can authorize credit dispatch."

    When SO.paidAmount < SO.totalAmount AND user role === 'admin':
    - Button label: "Ready (Credit)"
    - Amber/yellow styling (not red — this is allowed action)
    - Click → opens "Credit Dispatch Authorization" dialog:

      Dialog content:
      Title: "Authorize Credit Dispatch"
      Body:
        "Sales Order: SO-XXX
         Customer: [Customer Name]
         Total Amount: ₹X
         Paid: ₹Y
         Outstanding Credit: ₹Z

         Customer Payment Terms: [Net 30]
         Credit Limit: ₹A
         Current Outstanding: ₹B

         [If B + Z > A: amber warning] 'Approving this dispatch will
         exceed the customer's credit limit by ₹(B+Z-A).'

         [Reason textarea, required]
         placeholder: 'e.g., Long-term customer with strong payment
         history; cash flow constraint this month; strategic deal
         negotiated by CEO'

         [Cancel] [Authorize Credit Dispatch]"

      Authorize button disabled until reason has at least 10 characters.
      On authorize: call mutation with creditOverride=true,
      creditReason=text; spinner; on success close dialog, refresh
      challan list.

C3. Reasoning for the credit_amount captured at override time:
    - At the moment of override, the outstanding amount is fixed
    - Subsequent customer payments will reduce SO.paidAmount but the
      challan's credit_amount stays as the snapshot
    - This makes auditing clean: "On May 5, CEO approved ₹2,30,000
      credit. As of May 30, ₹1,50,000 is still owed."
