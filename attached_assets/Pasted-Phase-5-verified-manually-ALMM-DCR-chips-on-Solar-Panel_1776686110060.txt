Scope as per ticket:
1. New endpoint: POST /api/products/import

Multipart form, accepts CSV file
Query param mode=dry_run|commit
Dry Run validates and shows preview, writes nothing
Commit runs full import inside a single transaction

2. CSV columns (in this order for the downloadable template):
name, sku, brand, category, description, distributorPrice, logisticsCost, unitPrice, targetMarginPct, gstRate, hsnCode, unit, minStockLevel, minMarginPct, warrantyPeriod, mrp, type, packSize, almm, dcrCompliant, modelSeries, lifecycleStatus, applicableRegions, priceListVersion, productFamily, customerTierPrice (JSON), specs (JSON), supplierSku
Required columns: name, category. Everything else optional/nullable.
3. Validation rules:

Category must match one of the 16 predefined categories (reject row if not)
Brand: auto-create if not found (case-insensitive match against existing brands first). When auto-creating, set isActive = true and leave defaultMarginPct null.
SKU: if blank, auto-generate as {brand_prefix}-{timestamp_base36} (same pattern as manual entry in Phase 2)
Existing SKU in DB: skip the row, add to error report (don't overwrite)
Duplicate SKU within same CSV file: flag in Dry Run preview with row numbers, operator decides abort vs proceed (if proceed, only first row imports, rest skipped)
unitPrice: if blank AND both distributorPrice and logisticsCost are present, auto-compute as (distributorPrice + logisticsCost) × (1 + gstRate/100) × (1 + targetMarginPct/100). Uses targetMarginPct from the row if present, otherwise falls back to a per-import-dialog default the operator can set.
logisticsCost: if blank, auto-compute as distributorPrice × 0.02 (2% default)
priceListVersion: if blank, auto-stamp from a single field at the top of the import dialog (operator enters version once, applies to all rows)
applicableRegions: stored as text array. Accept comma-separated values in CSV (e.g., "North,East,Northeast") or keyword "All India" which stores as NULL
customerTierPrice: accept as JSON string in CSV. Validate 2 rows: end_user, business. Reject if shape is wrong.
specs: accept as JSON string in CSV. Validate against category template if category has one; otherwise accept any key-value shape. Reject if malformed JSON.
almm, dcrCompliant: accept "true"/"false"/"yes"/"no"/"1"/"0" case-insensitive. Null if blank.
lifecycleStatus: accept "active"/"discontinued"/"replaced"/"draft" case-insensitive. Default to "active" if blank.

4. Supplier products auto-link:
When a row's brand value matches an existing supplier name (case-insensitive), auto-create a supplier_products row:

supplierPrice = distributorPrice from the row
supplierSku = from CSV column if provided, else NULL
isPrimary = true, unless another isPrimary link already exists for that product (then false)

This handles the common case where your suppliers ARE the brands (Eastman = brand + supplier).
5. Transaction safety:

Commit mode: entire import inside single DB transaction. If any row fails critical validation, either (a) abort entire import, or (b) skip bad rows and commit valid ones — your call which pattern is cleaner. Document whichever you pick.
Dry Run: NO database writes under any circumstance. Validate, report, done.

6. Response shape:
{
  mode: "dry_run" | "commit",
  imported: number,
  skipped: number,
  errors: [{row_number, sku, product_name, error_type, error_message}],
  duplicates_within_file: [{row_number, sku, first_occurrence_row}]
}
