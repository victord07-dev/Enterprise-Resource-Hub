Fix 1 — Bundle component qty must be integer when unit is pcs/box/set
Screenshot shows qty field accepting "4.06" with decimal steppers in the bundle components editor. This is wrong for countable units.
Client (Products.tsx, bundle components editor):

Qty input's step and parsing depend on the selected component's unit:

If unit in {pcs, box, set}: step="1", enforce integer via onChange (reject non-integer input or round on blur), save as integer.
If unit in {kg, ltr, mtr}: step="0.01", allow decimals, save as float.
If unit in {WP, Ah, KWh} (spec units — shouldn't appear as stock units in bundles, but defensive): treat as integer.


When user changes the component selection, re-evaluate the step/validation based on the newly selected component's unit. Trim existing decimal if switching from a decimal-allowed unit to an integer-only unit (round DOWN to be safe, and show a toast "Qty adjusted to X — fractional units not allowed for pcs").

Server (shared/schema.ts Zod validator for product_bundle_items):

Reject qty with decimal portion when the resolved component's unit is pcs/box/set. Error message: "Quantity must be whole number for unit '[unit]'."
