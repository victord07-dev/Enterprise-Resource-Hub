Phase: Document Lifecycle Hardening — Challan, Sales Invoice (upload-only),
       GRN with Supplier Document Uploads, E-way Bill Capture

CONTEXT

The system currently lets users create challans regardless of stock or
payment status, lets sales invoices generate without proper sequencing,
and confirms GRNs without supplier challan proof. This phase adds
operational discipline that mirrors real ITFI workflow:

- Every physical document follows: generate (where applicable) → download
  → physical sign → scan back → upload → status advances.
- Sales invoice tax compliance is handled OUTSIDE the system (by accounts
  team in Tally / ClearTax). Our system only captures the sales invoice
  as a reference shell + uploaded signed scan + e-way bill capture.
- Cross-team coordination via notifications: sales creates draft challan
  to signal supply/accounts/inventory teams; those teams act on
  procurement / payment / stock readiness.

This phase covers:
- Delivery Challan lifecycle (sales-side, with PDF generation)
- Sales Invoice (auto-created on challan dispatch, upload-only — NO PDF
  generation by us)
- GRN lifecycle (purchase-side, with supplier challan upload before GRN
  creation, and supplier tax invoice optional upload on GRN)
- E-way Bill capture on sales invoice

SECTION B — DELIVERY CHALLAN LIFECYCLE

B1. Create draft challan from a Sales Order (existing flow + additions):
    - Available to: sales, sales_manager, admin
    - Status='draft' on creation
    - On creation: send notification to roles [inventory, accountant,
      admin] with payload: "Draft Challan #[NUMBER] created for SO
      #[NUMBER]. Stock + payment review required."
    - Sales user sees toast: "Draft challan created. Inventory and
      accounts notified."
    - Audit log: action='challan_drafted'

B2. Sales Order detail page — add "Documents" panel showing:
    - Linked challan(s): number, status badge, signed copy uploaded ✓/✗,
      action buttons per status + role
    - Linked invoice(s): number (if recorded), status badge, signed copy
      ✓/✗, e-way bill ✓/✗

B3. Download draft challan PDF:
    - Available on draft, awaiting_signature, and dispatched statuses
    - PDF format: 2-copy layout — print produces two copies on the same
      page or two pages, labeled "OFFICE COPY" and "DRIVER COPY" (or
      "ACKNOWLEDGMENT COPY")
    - Each copy includes: customer details, line items, qty, signature
      line at bottom: "Authorized Signatory: ______________ Date: ______"
    - DRAFT watermark on PDF when status='draft'
    - No watermark once status moves beyond draft

B4. Mark Ready for Signature (transition: draft → awaiting_signature):
    - Available to: accountant, sales_manager, admin, inventory
    - Hard-blocked unless BOTH:
      a. Stock is sufficient for ALL line items in the SO/challan
         (existing 0-stock check — preserve and extend)
      b. Linked Sales Order is fully paid (sum of customer payments =
         SO total exactly)
    - If blocked: show specific reason via tooltip on the disabled
      button. E.g., "Cannot proceed: short stock on Item X (need 5,
      available 2)" or "Customer payment incomplete: Outstanding
      ₹50,000".
    - On success:
      * Status → 'awaiting_signature'
      * ready_for_signature_at, ready_for_signature_by recorded
      * Notification to sales_manager + admin: "Challan #[NUMBER] ready
        for printing and signature."
    - Audit log: action='challan_ready_for_signature'

B5. Upload Signed Copy:
    - File upload field on challan detail page, available when status
      = 'awaiting_signature'
    - Accepts PDF, JPEG, PNG (max 10 MB)
    - Available to: any user with access to the SO
    - Stores signed_copy_url, records uploader + timestamp
    - Multiple uploads allowed (replaces previous; old URL audit-logged)
    - Audit log: action='challan_signed_copy_uploaded'

B6. Dispatch Challan (transition: awaiting_signature → dispatched):
    - Available only when status='awaiting_signature' AND
      signed_copy_url IS NOT NULL
    - Hard-block button if signed copy missing — tooltip "Upload signed
      copy before dispatching"
    - Available to: accountant, sales_manager, admin, inventory
    - On dispatch:
      * status='dispatched'
      * dispatched_at, dispatched_by recorded
      * Stock movement created (existing logic — preserve)
      * Inventory deducted (existing logic — preserve)
      * AUTO-CREATE sales_invoice row:
        - sales_order_id, delivery_challan_id, quotation_id linked
        - status='pending_upload'
        - invoice_number, invoice_date, total_amount, gst_amount left
          NULL — accounts team fills via Sales Invoice page
        - All other fields NULL
      * Notification to accountant + admin: "Challan #[NUMBER]
        dispatched. Sales Invoice pending upload — record invoice
        details from Tally."
      * Notification to sales: "Challan #[NUMBER] dispatched."
    - Audit log: action='challan_dispatched' + 'sales_invoice_auto_created'

B7. Cancel Challan:
    - Available on draft and awaiting_signature only
    - NOT available after dispatch (returns are out of scope)
    - Required: cancellation_reason
    - Sets status='cancelled', no stock movement
    - Audit log: action='challan_cancelled'

SECTION D — GRN LIFECYCLE (PURCHASE-SIDE)

D1. NEW SEQUENCE: Supplier challan upload comes BEFORE GRN creation.
    The GRN cannot be created until the supplier challan scan is
    uploaded. The flow is:

    Step 1: User on PO detail page sees "Receive Goods" section
            (visible when PO is approved + has been paid in full to
            supplier — full supplier payment required, similar to sales
            full-payment requirement). If supplier payment incomplete,
            section shows: "Cannot create GRN: full payment to supplier
            required before goods receipt."

    Step 2: User clicks "Upload Supplier Challan" → file upload modal
            (PDF / JPEG / PNG, max 10 MB)
            - Stored temporarily as a pending upload tied to the PO
            - Audit log: action='supplier_challan_uploaded_for_grn'

    Step 3: After upload, user clicks "Create GRN" button
            - System creates grns row with status='draft'
            - supplier_challan_url, supplier_challan_uploaded_by/_at
              populated from Step 2
            - User then enters per-line item received quantities (matches
              or differs from PO; track discrepancy)
            - Audit log: action='grn_drafted'

D2. Download draft GRN PDF:
    - Format: itemized goods received, supplier reference, PO reference,
      date, signature line at bottom
    - DRAFT watermark when status='draft'

D3. Upload our signed GRN copy:
    - File upload on GRN detail page, available when status='draft'
    - PDF/JPEG/PNG, max 10 MB
    - Stores signed_copy_url + uploader + timestamp
    - Audit log: action='grn_signed_copy_uploaded'

D4. Confirm GRN (transition: draft → confirmed):
    - Hard-blocked unless signed_copy_url IS NOT NULL
    - (supplier_challan_url is already required at GRN creation per D1
      so it's always present)
    - Available to: accountant, admin, inventory
    - On confirm:
      * status='confirmed'
      * confirmed_at, confirmed_by recorded
      * Stock added to inventory (existing logic — preserve)
      * GRN lots created for FIFO costing (existing logic — preserve)
      * Notification to admin + accountant: "GRN #[NUMBER] confirmed.
        Stock updated."
    - Audit log: action='grn_confirmed'

D5. Upload Supplier Tax Invoice (optional, any time):
    - File upload field on GRN detail page
    - Available before or after GRN confirmation
    - Optional fields: supplier_invoice_number, supplier_invoice_date
    - Stored in supplier_invoice_url, supplier_invoice_*_by/_at
    - If GRN confirmed and supplier_invoice_url is null, show banner on
      GRN: "Supplier tax invoice pending upload."
    - Audit log: action='grn_supplier_invoice_uploaded'

D6. Cancel GRN:
    - Available only on draft status (not after confirmation — stock has
      moved)
    - Required: cancellation_reason
    - Status='cancelled', no stock changes
    - Audit log: action='grn_cancelled'
