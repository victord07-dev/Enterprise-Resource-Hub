2. The Four Hard Problems Your Current System Cannot Handle
Problem 1: Bundle / Kit Products (BOS Kit + Lith Combo)
Solar BOS Kit — Sold as 1 SKU (₹10,450) but physically contains 22 individual
components (cables, connectors, earthing rods, etc.), each with its own unit of measure
(NOS, MTR, KG).
Solar Lith Combo — 55+ bundle SKUs. Each combo is:

1× PCU (e.g. EM SS 1250-12V) at its own cost
1× LFP Battery (e.g. LFP-160 at ₹13,820)
1× Solar Panel (e.g. EMP210W at ₹4,100)
= Combo Basic Price (e.g. ₹23,110)

The current system sells one product → one stock unit. Bundles need:

Stock deducted from each component when a bundle is sold
Pricing optionally derived from component prices

→ Current system: CANNOT handle. See solution in Section 5.

Problem 2: Volume / Tier Pricing (Solar Panel Pallets)
Solar panel pallet pricing varies by quantity ordered:
Model2 Pallets4 Pallets8 PalletsEBP500W-DCR (North)₹11,550/panel₹11,380/panel₹11,310/panelEBP550W-DCR (North)₹12,199/panel₹12,007/panel₹11,924/panel
The daily pricing engine stores ONE confirmed price per product per day.
It cannot express "price depends on quantity ordered."
→ Current system: CANNOT handle. See solution in Section 5.

Problem 3: Regional Pricing (Solar Panel Pallets)
The same panel model (EBP500W-DCR) has different distributor prices depending on
delivery region:
Region2 Pallets4 Pallets8 PalletsNorth (HR,HP,PB,RJ,UP,UK,BH,JH,MP,CG,MH,GJ,Goa)₹11,550₹11,380₹11,310South+East (WB,NE,Orissa,AP,TG,KA,KL,TN)₹11,650₹11,480₹11,410
Your customer's delivery state determines which price applies.
The current system has no concept of customer region → price variation.
→ Current system: CANNOT handle. See solution in Section 5.

Problem 4: No Technical Spec Fields
Every product type from Eastman has structured specs that your sales team NEEDS to
quote correctly. Currently all of this would go into description as unstructured text,
meaning:

Can't filter "show me all 48V-compatible products"
Quotation PDFs can't show specs in a structured way
Sales staff can't match panel wattage → PCU compatibility

→ Current system: Can be fixed with a JSONB specs column. See Section 6.

⚠️ Your current form defaults to 18%. All solar PCUs/inverters/batteries
should be 12%. Solar panels are 0%. Entering wrong GST will cause every
invoice to overcharge customers and create GST filing discrepancies.

Auto-suggest GST based on category in the product form — add this to handleTypeChange:
typescriptconst categoryGSTDefaults: Record<string, string> = {
  "Solar PCU / Inverter":       "12",

};
// When user changes category, auto-set gstRate:
setProductForm(prev => ({
  ...prev,
  category: v,
  gstRate: categoryGSTDefaults[v] ?? prev.gstRate,
}));

5. New Features Required (Development Tasks)
Feature A: Bundle / Kit Engine (Priority: HIGH)
Needed for: Solar BOS Kit, all 55+ Lith Combo products.
Schema
sql-- New table
product_bundle_items (
  id            UUID PRIMARY KEY,
  parentId      UUID NOT NULL REFERENCES products(id),
  componentId   UUID NOT NULL REFERENCES products(id),
  quantity      NUMERIC(10,3) NOT NULL,
  unit          VARCHAR(20)   -- can differ from parent product unit
)

-- New product type value
-- products.type: 'product' | 'service' | 'bundle'  ← add 'bundle'
Behaviour Rules
When a bundle is SOLD (quotation / sales order):
  → Deduct stock from each component product (not from bundle itself)
  → Bundle has no stock of its own

When a bundle is RECEIVED via GRN:
  → Two options (pick one per product):
    (a) Receive as components (GRN each component individually)
    (b) Receive as bundle unit → system splits into components

Bundle pricing:
  → Option 1: Manual price set on bundle (like BOS Kit at ₹10,450)
  → Option 2: Auto = SUM(component quantity × component effective price)
  → Both should be supported; set per bundle

Bundle product form additions:
  → "Components" section: add/remove component products with qty
  → "Pricing mode" toggle: Manual / Auto-calculated
Interim Workaround (Before Feature is Built)
Enter BOS Kit as a single product, describe components in description.
For Lith Combos: enter each combo as a separate product with the combo price.
Stock will not auto-deduct from components — track manually.

Feature B: Volume / Tier Pricing (Priority: MEDIUM)
Needed for: Solar Panel Pallet products.
Schema
sqlproduct_price_tiers (
  id          UUID PRIMARY KEY,
  productId   UUID NOT NULL REFERENCES products(id),
  minQty      INTEGER NOT NULL,
  maxQty      INTEGER NULL,      -- NULL means "and above"
  pricePerUnit NUMERIC(10,2) NOT NULL,
  region      VARCHAR(50) NULL,  -- NULL means applies to all regions
  effectiveDate DATE NOT NULL,
  createdAt   TIMESTAMP DEFAULT NOW()
)
Behaviour
When adding a line item in sales order / quotation:
  → If product has price tiers:
    1. Check customer's delivery region (from customer record)
    2. Check quantity entered
    3. Look up matching tier: WHERE region = customer.region 
       AND minQty <= qty AND (maxQty IS NULL OR maxQty >= qty)
    4. Auto-populate unit price from tier
    5. Show tier badge: "Pallet Tier Price (4 pallets, North zone)"

When quantity changes on the line item:
  → Re-check tier and update price if tier changes
  → Show warning if price changed due to tier
Interim Workaround (Before Feature is Built)
Create 3 separate product SKUs per panel model per region:

EBP500W-DCR-N-2P (North, 2-pallet price ₹11,550)
EBP500W-DCR-N-4P (North, 4-pallet price ₹11,380)
EBP500W-DCR-N-8P (North, 8-pallet price ₹11,310)

Clunky but functional. Replace with tier pricing engine when built.

Feature C: Customer Region Field (Priority: MEDIUM, needed for B)
Add deliveryRegion VARCHAR(20) NULL to customers table.
Values:
"North"      → HR, HP, PB, RJ, UP, UK, BH, JH, MP, CG, MH, GJ, Goa
"South_East" → WB, NE, Orissa, AP, TG, KA, KL, TN
"Pan_India"  → default (no regional variation)
Show as a dropdown on the customer form. Used by tier pricing engine.

9. One More Thing — Bulk Import
164 SKUs entered one-by-one through the dialog is ~3–4 hours of manual data entry
and prone to errors. Before entering any products, consider building a simple
CSV import endpoint first:
POST /api/products/import
Body: CSV file with columns:
  name, sku, brand, category, description, gstRate, hsnCode,
  unit, minStockLevel, minMarginPct, specs (JSON string), warrantyPeriod
This would let you prepare the Eastman catalog in Excel (from the price lists),
clean it up, and import all 164 rows in seconds. Would also be useful every time
Eastman releases a new price list (quarterly typically).
