Your action list, in order
Do these in this exact sequence. Each builds on the previous one, and getting them out of order wastes time or produces ambiguous results.
1. Set the env flag in production (2 minutes)
Open Replit's deployment settings for the production service (not workspace). Add:
WHATSAPP_DEBUG_CAPTURE_TYPES=message_received
Save and restart the production service. The env flag doesn't activate until restart.
2. Confirm the flag is live (1 minute)
Open the deployed app, log in as admin, go to WhatsApp Templates page. Look at the Health card's "Debug captures" section header. It should say enabled: message_received. If it still says disabled, the restart didn't pick up the env var — check the Replit deployment logs for the startup line and retry.
3. Eyeball the rest of the Health card (2 minutes)
While you're there, check the three config flags in the Config section. All three — WHATSAPP_WEBHOOK_BASE_URL, WHATSAPP_WEBHOOK_TOKEN, INTERAKT_WEBHOOK_SECRET — must be green. If any is red, fix it before re-enabling the webhook, otherwise every Interakt call will be rejected.
Note the exact URL shown in the Config section. You'll need it in step 5.
4. Send the Interakt support email (3 minutes)
Open .local/artifacts/interakt-support-email.txt. Read it. If the three questions are specific and numbered, send as-is from your account to [email protected]. This starts the support-reply clock independent of everything else.

Open the webhook configuration.
Confirm the URL matches what the Health card Config section shows exactly. Same protocol, same domain, same path, no trailing slash differences.
Confirm these event subscriptions are enabled: inbound message / message_received, message sent, message status (sent, delivered, read), failed message delivery, template status updates.
Hit "Test webhook" if available, otherwise re-save.
Check Interakt's "Webhook Deliveries" log — the test should show a 200 response from your endpoint.

What to do if something doesn't work
You have four diagnostic surfaces now, so don't debug by guessing. Each surface tells you something specific:
SymptomFirst place to lookMessage sent, nothing arrives at all within 60sInterakt dashboard's webhook delivery log — did Interakt try to send?Interakt shows it sent but your app didn't acceptHealth card's rejected-payload viewer — what's the reason code?Accepted but not appearing in inboxHealth card's pending/processing/failed stats + dead-letter listMessage appears but no media attachmentDebug captures — what does the payload actually look like?
If the reason code is token_mismatch or hmac_mismatch or secret_missing, it's a config issue (token/secret mismatch between your env and Interakt) — fix that.
If it's parse_error, Interakt sent something your handler doesn't understand — the rejected-payload viewer shows exactly what. Paste it to Replit AI.
If nothing shows in any of these four surfaces within a few minutes of sending a test message, the webhook URL itself is probably wrong — go back to step 5 and double-check.
